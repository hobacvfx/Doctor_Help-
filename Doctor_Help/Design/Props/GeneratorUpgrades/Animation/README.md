# Generator upgrade animations

Four standalone Unity prefabs: `Assets/Prefabs/Basement/GeneratorUpgrades/Generator_LV1.prefab`, LV2, LV4 and LV5. Existing LV3 (`Assets/Prefabs/Basement/generator.prefab`) is preserved. These are animated assets; this change does not add an upgrade shop, prices or electricity balancing.

Each `LV*/` contains an editable Spine **4.3.26 Essential** project, authoring JSON and separate transparent body/rotor PNGs. Production Unity atlases/data/materials are in `Assets/Art/Props/GeneratorUpgrades/Generator_LV*/`. Straight-alpha input, sRGB, no mipmaps, max 2048, Android/iOS ASTC 6x6. Art parts were extracted from the approved concepts with built-in imagegen; see `Production_Prompts.txt`. Native technical slicing removes low-alpha generation haze and crops the parts without redrawing them.

Each rig has `Idle` (one-second static loop) and `Operating` (two-second loop). LV1 crank rotates at 180°/second, LV2 flywheel at 360°/second, LV4 fan at 540°/second and LV5 fan at 720°/second. Body scale changes only ±0.3%, without position jitter. Bearings, belts, gauges, casing and bezels remain fixed; the rotor has its own hub pivot. LV5 retains its illuminated display/status lamps. Matching first/last poses permit continuous looping.

Use the existing `GeneratorAnimationController.SetOperating(bool)` API on each prefab. They default to Idle. Wiring and production remain controlled by their existing gameplay systems.

`Generator_Upgrades_Operating.gif` combines actual Unity-rendered frames at 30 FPS; individual GIFs and selected PNG samples are in each `Preview/` folder. These are runtime Spine renders, not rotations of an assembled concept image.

Rebuild: run `SliceParts.ps1` with Windows PowerShell 5.1, then `BuildRigs.py` with Python. Import the authoring JSON using Spine CLI `-i <source.json> -o <project.spine> --to <name> --replace -r`. Export with **absolute output paths** and `--set packAtlas.premultiplyAlpha=false --set packAtlas.maxWidth=2048 --set packAtlas.maxHeight=2048 -e json+pack`; rename `.atlas` to `.atlas.txt`. Run `BuildRigs.py` again to wire Unity references. Existing GUIDs are reused.

Validation: `PrepareValidation.py` stages a small independent Unity project under Library; `Validate.cs.txt` executes production symptom-variant and generator code using a synthetic medical fixture. It tests equal distributions, invalid sets, session stability, anchors/clue IDs and cleanup; loads all four saved generator prefabs, samples native Spine movement and state changes, and renders the previews. No gameplay scenes or player saves are loaded. `Validation.txt` records results. Full gameplay Play Mode and Android device testing are not performed. Production runtime/editor assemblies also compile with Unity's Roslyn compiler against this project's normal references (one pre-existing AdMob obsolete-API warning).

After native rendering, `PrepareGifUtility.py` and `BuildPreviews.ps1` encode the GIFs; the latter requires Windows PowerShell 5.1. Intermediate frame PNGs can be regenerated by the isolated validation runner.
