# Generator upgrade shop

Player_Home now has an **Upgrade** world button beside the basement generator. It opens `Assets/Resources/UI/ClinicShops/GeneratorUpgradeShop.prefab`, using the same clean wood/clipboard, paper cards, font and shared sliced action-button frame as the existing furniture shops. It opens only during Preparation after the normal day-2 shop unlock.

The five item prefabs are `Assets/Resources/ShopItems/Generators/GeneratorLv1.prefab` through `GeneratorLv5.prefab`. Edit **ClinicShopItem → Price** on each item to set prices; they currently have placeholder **0**. LV1 is the free default generator; LV2–LV5 are sequential purchases that automatically equip. Owned levels can also be equipped from the existing Inventory. Ownership and equipped tier use the existing profile shop/equipment fields and autosave rules, without a new save schema.

Temporary production is centralized in `GeneratorUpgrades.EnergyPerDay`: LV1 15, LV2 25, LV3 35, LV4 45, LV5 55 electricity/day. Shop descriptions display this same live value. Production follows the equipped level, not the highest owned level; no equipped entry falls back to LV1. Generators are excluded from furniture electricity consumption. Other furniture continues to consume its existing daily amount.

`BasementDefenseService.ClaimDayProduction` claims the selected tier's output while the wiring is intact, otherwise 0. The existing day cache is retained for retries. At the end-of-day checkpoint, electricity becomes **max(0, previous + production − consumption)**, with a wide intermediate to avoid integer overflow. Generation is added before consumption and only the final balance is clamped. Gold continues to support debt. The old flat 50/day setting has been removed.

`GeneratorUpgradeStation.prefab` contains the editable world button, `ClinicFurnitureSlot`, `ClinicShopEntrance` and `GeneratorUpgradeView`. Home scene overrides link its camera, popup and legacy generator. The station keeps the previous machine position/scale; the legacy renderer is disabled at runtime. The furniture slot replaces the visual with the appropriate prepared Spine prefab, including the original LV3. BasementDefenseView forwards the simulation's working/broken state to the currently equipped machine. Buying a tier does not repair the wire or reset defense progress.

Thumbnail PNGs in `Assets/Art/Props/GeneratorUpgrades/Icons/` are native Spine renders with transparent backgrounds, no mipmaps and ASTC 6x6 overrides for Android/iOS. `GeneratorShop.png` is a native UI preview using the placeholder prices.

Validation uses an isolated Unity project under `Library/GeneratorShopValidation`, containing copies of the production runtime sources/assets. All writes use `TutorialPreviewSession`; real player saves and the open gameplay scene are untouched. Tests cover sequential unlocks, purchase/equip, duplicate/insufficient-gold rejection, production by equipped tier, broken wiring, cached retry production, save/reload, nonnegative end-of-day energy and failed-checkpoint retry. A projection of the exact new Home prefab instances verifies native scene references without running the whole Home scene. See `Validation.txt`. This is manually stepped Editor validation, not full Home/Office Play Mode, touch/device or AAB-build testing.

Rebuild assets with `BuildAssets.py` (existing item prices are preserved). `PrepareValidation.py` stages the isolated project; `PrepareSceneProjection.py` stages native scene-reference fixtures; `Validation.cs.txt` is its Editor runner and thumbnail renderer. Asset creation reuses existing art/UI; no new AI illustration is generated for this shop.

Generator actions share one position, centered above the currently equipped machine. `GeneratorUpgradeView` anchors both transforms once when the equipped model changes, after its initial Spine mesh is ready; it then keeps that position fixed through Operating/Idle animation and action switches. It must not follow animated renderer bounds each frame or add button bounce. `actionTopSpacing` is editable in the station prefab. It owns action visibility: working shows Upgrade (subject to the existing day-2 shop unlock), broken shows Repair. It hides the old action before showing the next. `ClinicShopEntrance.SetAvailable` combines this machine-state gate with its normal shop gate, so profile changes cannot reveal Upgrade while broken; it also cancels a pending open when the action becomes unavailable. BasementDefenseView only controls Repair directly for legacy scenes without a GeneratorUpgradeView. Prices, repair cost and wiring simulation are unchanged.

Both action frames and click areas still match the reception upgrade button's effective world size, including scaled parents. `FixWorldButtons.py` writes the shared authoring position and scene links; `BuildAssets.py` reapplies them. `ActionSwitchValidation.txt` / `GeneratorAction_Working.png` / `GeneratorAction_Broken.png` are the current native state/position checks for all five tiers, repeated state changes and profile changes while broken. Earlier `ButtonValidation.txt` / `GeneratorButtons.png` document the superseded side-by-side layout. Preview renders use a temporary built-in sprite material; the game's URP materials remain unchanged.

Mobile readability: the standalone generator popup has a CanvasScaler matching the Home HUD (540x960, width match). It uses its own `GeneratorShopRow.prefab`: preferred height 300, minimum 280, name 26, description 22 and action label 24 reference units. Description/name/action text use the real OldStandardTT-Bold face without automatic shrinking. Larger portrait and text regions accompany the larger card. Other furniture shops retain their existing row sizing; descriptions and regular body/status text in the shared shop, medicine and inventory prefabs now use OldStandardTT-Bold. Basement plant text already used that face. `ApplyReadability.py` reapplies these authoring settings; prices, equipment and unlock rules are unchanged. `ReadabilityValidation.txt` and `Readability_360x800.png` / `Readability_720x1280.png` record native renders, text-wrap checks and button-size checks. No Android device test was performed.
